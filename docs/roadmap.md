## 현재 위치

**마일스톤 4(AI 퀀트봇)를 지켜보는 단계다.** 마일스톤 3(실거래)은 2026-10-07 사용자 확인으로 끝냈다 (태그 `milestone-3`). AI 봇("시장분석 AI 봇")은 운영에서 매일 판단하고 실제 토스 계좌에서 1/100로 따라 한다. 1~2주 지켜보고 사용자가 괜찮다고 하면 마일스톤 4를 끝낸다. 공개 데모 [demo.trading-lab.me](https://demo.trading-lab.me)(예시 시세·예시 AI 판단, 누구나)와 운영 `app.trading-lab.me`(실제 토스 시세, Access 본인만)는 개발 PC에서 함께 돈다. 다음 계획은 맨 아래 "앞으로 계획"(캔들분석 AI 봇, 서버 이전)이다.

## 진행 순서 (MWP, 모두 완료)

가장 불확실한 것(토스 API)을 먼저 확인하고, 서버 배포는 화면이 생기는 시점에 바로 해서 운영 검증 기간을 일찍 시작했다.

| Phase | 이름 | 상태 | 한 일 |
| --- | --- | --- | --- |
| 0 | 토스 API 검증 | 완료 | 토큰·허용 IP·일봉 이력·rate limit 확인 → [tossApi.md](tossApi.md). 첫 종목 `QQQ`, 봉 주기 일봉 결정 |
| 1 | 프로젝트 기반 | 완료 | uv 백엔드, ruff·mypy(strict)·pytest, 로컬 PostgreSQL 17, Alembic, Vite·React 골격, CI |
| 2 | 시세·전략·백테스트 (CLI) | 완료 | 일봉은 정규장 마감 + 2시간 뒤부터만 사용, 토스 어댑터(토큰 관리·백오프), 봉 검증·저장, 전략 인터페이스, T+1 시가 모의 체결, 백테스트 CLI(입력 조건 전부 저장) |
| 3 | Worker DRY RUN (로컬) | 완료 | advisory lock 단일 Worker, 판단·주문 중복 방지, 봇 상태 전이, 장애 주입 테스트, `replay`로 정기 평가와 백테스트 체결 일치 확인 |
| 4 | 배포·운영 화면 | 완료 | FastAPI·화면, 단일 Docker 이미지·운영 Compose, bootstrap·deploy·backup 스크립트, Terraform(`infra/lightsail`). 서버는 아직 개발 PC (아래 "서버 이전") |
| 5 | MWP 마무리 | 완료 (2026-10-04) | 백테스트·설정 화면, 한계 문서화. **2주 무개입 운영과 백업 복원 연습은 하지 않기로 했다** (사용자 결정: 운영하면서 고치고, 복원 절차는 필요할 때 만든다) |

**유명 전략 4종은 없앴다 (2026-10-08, 사용자 결정):** 이동평균 교차·200일선·RSI2·돈치안은 MWP에서 파이프라인(판단·체결·replay 일치)을 검증하는 데 썼다. 2010년 이후 강세장에서 어떤 추세 전략도 매수 후 보유를 넘지 못하고 낙폭만 줄였고, 지금은 "나를 대신해 투자하는 앱"에 맞지 않아 뺐다. 이유는 project.md 결정 표 "유명 전략 4종 제거".

**운영 교훈 (2026-10-02):** 개발 PC는 Windows 업데이트 재부팅·로그인 전 Docker 미기동으로 약 5시간 멈춘 적이 있다 (Healthchecks가 정상 감지). 그래서 재시작 뒤 `PAUSED`로 두던 규칙을 "실행 중이던 봇은 이어서 실행"으로 바꿨고, 근본 해결은 서버 이전이다.

## 따라 하기 트랙 (완료)

과거("그때 ~할 걸")는 평행세계의 나가, 미래는 봇이 **다음에 할 일**을 알려 준다. 사용자가 실제 계좌에서 같은 날 같은 금액으로 따라 하면 그대로 실제 투자가 된다. 규칙은 바꾸지 않고 보여주기만 하므로 백테스트·DRY RUN 일치(원칙 3)는 그대로다.

| 단계 | 내용 |
| --- | --- |
| F1 | **다음에 할 일:** 다음 입금일과 종목별로 살 금액·모아 둘 금액·이유 (내일 체결될 예정 주문이 있으면 그것부터) |
| F2 | **조건까지 거리:** "이 가격 아래면 몰아 사요", "이 가격 위면 그달은 쉬어요"와 지금 가격까지 남은 % |
| F3 | **모아 둔 돈 설명:** 어느 달 어느 종목 몫에서 왔는지 |
| F4 | **비율 맞추는 나 (평행세계):** 새 돈을 덜 든 종목부터 사서 처음 비율로 돌아가는 나. 매수 타이밍이 핵심이라 실제 봇 규칙에는 넣지 않는다 (사용자 판단) |

## 원화로 보기 (완료)

미국 주식은 늘 달러이고 원화는 바꿔 보기만 하는 기준이다. 봇은 처음부터 달러로 돈이 들어가므로 환전 당시 환율(원화 원가)은 다루지 않는다 (사용자 결정). **W1:** 토스 환율 API의 매매기준율로 하루 몇 번 최신 값 하나를 저장하고, 화면에서 $ / ₩를 바꾼다 (전략·주문·DB는 그대로 달러). 환차익·환차손은 보이지 않는 한계가 있다. 실제 환전 기록이 생기면 그때 원화 원가·환전 비용·양도세를 다시 본다.

## 실거래 트랙 (마일스톤 3, 완료)

**목표:** 나 카피 봇의 모의 투자를 **1/100 축소판으로 실제 토스 계좌에서 따라 산다.** 판단은 모의와 같은 함수이고, 다른 것은 "줄인 금액으로 실제로 보낸다"는 마지막 한 걸음뿐이다 (원칙 3).

**왜 축소판인가 (사용자 결정):** 실제 큰돈 투자(목표 매달 10만엔 ≈ 100만원)는 일본 moomoo에서 하고 이 앱과 잇지 않는다. 그래서 나 카피 봇(모의)은 실제 목표 금액으로 돌리고, 토스 계좌는 그 1/100로 같은 날·같은 종목·같은 비율로 산다. 모의는 "평행세계의 나"를 실제 크기로 보여주고, 실계좌는 같은 판단이 진짜 돈으로도 그대로 움직인다는 증명이다. 실제 주문 금액 = 모의 주문 금액 × 1/100 (센트 아래 버림). **비율은 키우지 않는다** (1/10 버튼은 2026-10-08에 없앴다). 처음에는 그림자 주문 2주 → 승인 모드 → 자동 → 고정 IP 서버를 계획했지만, 한 달 한두 번 1만원 남짓 사는 봇에는 과해서 줄였다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| R0 | **준비 (사용자):** 토스 계좌에 돈 넣기, 운영에 나 카피 봇 만들기 | 완료 |
| R1 | **실제 계좌 읽기:** Worker가 한 시간마다 주문 가능 금액(달러·원)·보유·최근 주문을 읽어 저장하고 설정에 보여준다 (계좌번호는 저장하지 않음, 주문 경로 없음) | 완료 |
| R2 | **실주문:** 주문 어댑터(`Trader` 규약, 금액 주문), 판단 다음 거래일 정규장 시작 5분 뒤 보내기, 체결 확인, 홈 승인 카드, 설정 "실제로 따라 하기", 비상 중지, 계좌 대조 | 완료 |
| R2+ | **화면 정리:** 설정 맨 위 "계좌와 알림", 홈 실제 계좌 카드(누르면 금액 가리기), 텔레그램을 화면에서 켜고 범위 고르기, 1/100로 줄인 몫이 $1보다 작으면 모아 두었다가 다음 주문에 더해 사기 | 완료 |
| R3 | **넓히기:** 비율은 1/100만, 레버리지는 QLD·TQQQ만, 파는 전략도 실거래(AI 봇의 일부 팔기: 이 봇이 실제로 산 수량 중 모의로 판 비율만큼), 고정 IP 서버는 별도 인프라 트랙으로 뺐다. 팔기는 몇 년에 한 번이라 실측 없이 끝냈다 | 완료 |

| 시간 | 접수 시간 안에 못 내면(PC 절전 등) 넘기고 알린다 |

**엔진과 증권사의 경계:** 엔진(domain·application·persistence·worker·API·화면)은 `domain/broker.py` 규약만 알고, 토스 규칙(멱등 키 형식·접수 시간·오류 코드·계좌 헤더)은 어댑터 안에서 규약의 값으로 바꿔 넘긴다 (project.md 4절, 사용자 결정).

**목표:** 내가 정해 준 규칙을 대신 지키는 봇이 아니라, **AI가 시장을 조사하고 판단해 내가 정해 준 종목 안에서 사고파는 봇.** 설계는 project.md 14절.

### 캔들분석 AI 봇

지금의 AI 봇은 뉴스·금리·실적 같은 **시장 상황**을 조사해 판단한다 (이름: "시장분석 AI 봇"). 이것과 다르게 **가격 캔들(차트)의 모양을 보고 판단하는 AI 봇**을 따로 더한다 ("캔들분석 AI 봇").

- **같은 뼈대:** AI는 종목·현금의 목표 비중만 정하고, 체결·한도·중복 방지·입금은 엔진이 한다 (project.md 14절 "나누는 선"). `Advisor` 규약과 판단 기록(`ai_judgments`)을 그대로 쓰고 **입력(캔들)과 지침만 다르다.**
- **구분:** 전략 하나를 더한다 (`ai_candle`). 봇은 전략마다 하나만 만들 수 있으므로(2026-10-08 규칙) 시장분석 AI 봇과 캔들분석 AI 봇이 각각 하나씩 생기고, 이름("시장분석 AI 봇"·"캔들분석 AI 봇")으로 구분한다.
- **비교:** 시작한 날부터 같은 돈으로 시장분석 AI 봇·캔들분석 AI 봇·나 카피 봇·매달 그냥 사기를 나란히 본다 (나중에 시작한 AI 봇 화면에 먼저 시작한 AI 봇이 같은 날 시작했다면으로 함께 나온다). 점수·판정은 붙이지 않는다.
- **설계 확정 (2026-10-08, 자세한 것은 project.md 14절 "캔들분석 AI 봇"):** 익명화한 숫자 표(종목마다 일봉 90개 + 주봉 52개, 판단일 종가 = 100, 종목 이름·날짜 숨김, 거래량 뺌), 웹 검색 없음, 시작한 날부터 앞으로만 비교(과거 백테스트로 성과를 말하지 않는다), 한 달 비용 상한은 시장분석과 따로(가안 $5), 토스 시세 원본 일봉을 AI에 보내는 것은 사용자 확인. 기업 분석(가치·실적)은 이 봇에 넣지 않고 시장분석 AI 봇의 몫이다.
- **구현 (순서):**
  - [x] ① 엔진과 데모: 전략 `ai_candle`, 익명 입력(지수화·글자 섞기·되돌리기, `domain/candles.py`), 비용 상한을 전략별로(`AI_CANDLE_MONTHLY_BUDGET` 기본 $5, 판단 기록에 전략), 데모 예시 판단과 `seed-demo` 예시 봇

  - [x] ③ 화면: AI 봇 묶음에서 아직 없는 종류마다 [+ 만들기], 캔들 봇 판단 화면(검색어·기사 대신 "차트만 보고 판단" 안내), 비교 카드에 봇 이름, 봇 화면·설정의 봇별 이번 달 비용

## 이미 끝낸 운영 항목

- **배포 자동화:** 운영은 `main` CI 통과 뒤 GitHub Actions가 이미지를 빌드해 GHCR에 올리고, 운영 서버의 self-hosted 러너가 받아서 배포한다 (공개 포트 0개 유지, 판단 시간 피함, 롤백은 `TAG=<커밋 해시>`). 데모는 수동 유지 (사용자 결정). DB는 운영 Postgres 컨테이너 하나에 데이터베이스 둘(`quant_lab`, `quant_lab_demo`)이다 (2026-10-08). 서버를 옮기면 그 서버에 러너만 다시 등록한다.
- **알림:** 설정 → 계좌와 알림에서 끄기 / 실제 주문만 / 모의 투자 소식까지, 테스트 메시지. 외부 heartbeat(Healthchecks)는 유지.
- **공개 서비스화:** 하지 않는다 (2026-10-03 결정). 시세 계약(최소 월 $250), 자문·일임 규제, 멀티유저 구조가 걸림돌이다 (project.md 12절).
