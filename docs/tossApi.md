# 토스증권 Open API 조사

> 출처: 공식 문서 `https://openapi.tossinvest.com/openapi-docs/` (overview.md, faq.md, OpenAPI JSON **v1.2.19**). 조사일 2026-10-01.
> 이 문서는 **공식 문서에 적힌 사실**과 **직접 호출로 확인한 사실**을 구분해 적는다. 확인 전 항목은 `미확인`으로 둔다.

## 1. 한눈에 보기

## 2. 시작 절차 (공식)

1. 토스증권 WTS 로그인 → 설정 > Open API에서 `client_id`, `client_secret` 발급
2. 같은 화면 하단 **허용 IP 관리**에서 호출할 공인 IP 등록
3. `POST /oauth2/token` (form-urlencoded: `grant_type=client_credentials`, `client_id`, `client_secret`)
4. 모든 호출에 `Authorization: Bearer {access_token}`. 계좌·주문·조건주문 API는 `X-Tossinvest-Account: {accountSeq}` 추가

Base URL: `https://openapi.tossinvest.com`, WebSocket: `wss://openapi-ws.tossinvest.com/ws/v1`

## 3. MWP에서 쓰는 엔드포인트

| 엔드포인트 | 용도 | Rate limit 그룹 (초당) |
| --- | --- | --- |
| `POST /oauth2/token` | 토큰 발급 | `AUTH` 5 |
| `GET /api/v1/candles` | 1분봉·일봉 | `MARKET_DATA_CHART` 20 |
| `GET /api/v1/prices` | 현재가 (최대 200종목) | `MARKET_DATA` 15 |
| `GET /api/v1/stocks` | 종목 정보 (상장 상태, 레버리지 배수 등) | `STOCK` 5 |
| `GET /api/v1/market-calendar/US` | 미국 장 운영 시간 | `MARKET_INFO` 3 |
| `GET /api/v1/exchange-rate` | KRW↔USD 환율 (화면 원화 보기, W1). `baseCurrency`·`quoteCurrency` 필수. 응답 `rate` = **살 때 환율**, `midRate` = **매매기준율**, `basisPoint` = 둘의 차이, `validFrom`~`validUntil` = 보통 1분. 1분마다 바뀌는 참고용 표시 환율이라 실제 주문 때 적용되는 환율과 다를 수 있다 (명세 v1.2.19, 2026-10-04). 화면 환산에는 `midRate`를 쓴다 | `MARKET_INFO` 3 |
| `GET /api/v1/commissions` | 매매 수수료율 (비용 가정 근거) | `ORDER_INFO` 6 · 계좌 헤더 필요 |

한도는 사전 공지 없이 바뀔 수 있다. 모든 응답의 `X-RateLimit-Limit/Remaining/Reset` 헤더를 기록하고, `429`면 `Retry-After`만큼 기다린 뒤 지수 백오프와 jitter를 적용한다.

### 캔들 `GET /api/v1/candles`

| 파라미터 | 값 |
| --- | --- |
| `symbol` (필수) | US는 티커 (`VOO`). `[A-Za-z0-9.-]` |
| `interval` (필수) | `1m` \| `1d` |
| `count` | 1–200, 기본 100 |
| `before` | ISO 8601, **inclusive**. 응답의 `nextBefore`를 그대로 전달. `+`는 `%2B`로 인코딩 |
| `adjusted` | 기본 `true` |

응답 `result.candles[]`는 **최신순(내림차순)**이다. 필드는 `timestamp`, `openPrice`, `highPrice`, `lowPrice`, `closePrice`, `volume`, `currency`이며 **가격·거래량은 decimal 문자열**이다 (float 변환 금지, `Decimal`로 파싱).

봉 시각 규칙:

- `1m`: **봉 종료 시각.** `[timestamp − 1분, timestamp)` 구간을 집계한다. 따라서 `timestamp <= now`인 봉도 막 끝난 직후에는 늦게 도착한 체결이 반영되지 않았을 수 있다. 완료 판정은 `timestamp + 여유 시간 <= now`로 한다.
- `1d`: 해당 거래일의 **현지 자정**. 미국 일봉의 OHLC는 **정규장 공식 종가 기준**이며 프리·애프터·데이마켓 체결은 포함하지 않는다. 거래량은 시간외가 섞일 수 있다.
- 1분봉 합계로 일봉을 재구성할 수 없다 (집계 범위가 다름). 일봉 전략은 일봉 API를 직접 사용한다.
- 체결이 없는 1분 구간은 직전 종가로 채운 **거래량 0 봉**이 내려온다 (오류 아님).
- 미국 1분봉은 장외·특수 체결이 섞인 **이상 고가·저가**가 있을 수 있고 걸러지지 않는다.

### 미국 장 운영 시간 `GET /api/v1/market-calendar/US`

- `date`(미국 현지 날짜) 기준으로 **전일·당일·익일 3영업일**만 반환한다. 세션은 `dayMarket`, `preMarket`, `regularMarket`, `afterMarket`이며 휴장이면 모두 `null`이다. 시간은 KST(+09:00).
- **연간 휴장일 목록은 주지 않는다.** 백테스트·장기 스케줄에는 `exchange_calendars`(XNYS)를 쓰고, 실행 시점의 개장 판정은 토스 캘린더를 우선한다. 둘이 다르면 신규 주문을 막고 경고한다.

## 4. 오류 처리 기준

응답 envelope: 성공 `{"result": ...}`, 실패 `{"error": {"requestId", "code", "message", "data"}}`. `requestId`(= `X-Request-Id` 헤더)는 항상 로그에 남긴다.

| 상황 | 코드 | Worker 동작 |
| --- | --- | --- |
| 토큰 만료 | `401 expired-token` | 재발급 1회 후 재시도 |
| 토큰 무효화 | `401 token-revoked` | **다른 프로세스가 토큰을 발급한 신호.** 재발급하되 반복되면 `ERROR` 전환 후 알림 (토큰 경합) |
| 허용 IP 아님 | `403 edge-blocked` / `forbidden` | 재시도 금지. `ERROR` 전환, 송신 IP를 로그에 표시 |
| 종목 없음 | `404 stock-not-found` | 해당 종목 비활성화 |
| 호출 한도 | `429 rate-limit-exceeded` 등 | `Retry-After` → 백오프 |
| 점검·장애 | `500 maintenance` / `internal-error` | 백오프 재시도. 데이터가 오래되면 신규 주문 차단 |

## 5. 나중 단계(실거래·실시간)에서 쓸 사실

- **주문 멱등성:** 주문 생성에 `clientOrderId`가 있다 (최대 36자, 영숫자·`-`·`_`). 같은 값으로 다시 보내면 이전 주문 결과를 그대로 돌려주고, 처리 중이면 `409 request-in-progress`, 내용이 다르면 `422 idempotency-key-conflict`. 내부 판단 키(`bot_id + symbol + bar_ts + mode`)에서 `clientOrderId`를 만들면 외부 주문까지 중복 방지를 이어갈 수 있다.
- **멱등성은 10분만 유효하다 (명세 v1.2.19, 2026-10-04 확인).** 10분이 지나 같은 값으로 보내면 **새 주문**이 된다. 또 주문 조회(`GET /orders`, `/orders/{orderId}`) 결과에는 `clientOrderId`가 없다 (주문 생성 응답에만 `orderId`와 함께 온다). 그래서 보내기 전에 DB에 먼저 적고, 응답의 `orderId`를 저장하며, 결과를 모르는 주문은 10분 안에서만 같은 키로 다시 보내고 그 뒤에는 종목·날짜·금액으로 주문 조회해 확인한다 (roadmap "실거래 트랙").
- **매수 가능 금액:** `GET /api/v1/buying-power?currency=USD|KRW` → `cashBuyingPower`(decimal 문자열, 미수 없는 현금 기준). Rate limit 그룹 `ORDER_INFO`, 계좌 헤더 필요. 원화로 달러 금액 주문이 되는지(자동 환전)는 명세에 없어 실제 주문 단계에서 확인한다.
- 동일 종목에 반대 방향 미체결 주문이 있으면 `409 opposite-pending-order-exists`.
- 미국 금액 주문은 정규장에서만 가능 (`422 amount-order-outside-regular-hours`).
- 레버리지·인버스 ETF는 앱에서 사전 요건(위험 고지 등)을 마쳐야 한다 (`422 prerequisite-required`).
- 짧은 시간에 소액 주문을 대량 반복하면 어뷰징으로 일정 시간 매매가 제한된다.
- 주문 조회는 주문 1건당 1행(평균 체결가·총 수량)이다. 건별 체결은 WebSocket `personal:order`만 제공한다.
- 조건주문(SINGLE·OCO·OTO)이 있다. 손절·익절을 서버 측 조건주문으로 거는 방식을 실거래 단계에서 검토한다.
- WebSocket: 계정당 동시 연결 2개 (초과 시 **가장 오래된 연결이 끊김**), 연결당 구독 100건, 선언 5회/초. 구독은 full-replace 방식이다. 클라이언트 송신이 180초 없으면 끊기므로 60초마다 `PING`을 보낸다. 시세 채널은 LOSSY(sequence 없음), 주문 채널은 세션 내 LOSSLESS이며 재연결 후 `GET /api/v1/orders`로 재동기화한다.

## 7. 실측 결과 (2026-10-01, 개발 PC, `scripts/toss_probe.py`)

원본 응답은 저장하지 않았다. 아래는 요약값이다.

**종목 (`/stocks`)**: 관심 목록 10종목 모두 `ACTIVE`, `USD`.

| 종목 | market | 유형 | leverageFactor |
| --- | --- | --- | --- |
| VOO, GLD, MAGS, EWY, EWJ | AMEX | ETF | 1 |
| QQQ | NASDAQ | ETF | 1 |
| QLD | AMEX | ETF | 2 |
| TQQQ | NASDAQ | ETF | 3 |
| SOXL | AMEX | ETF | 3 |
| NVDA | NASDAQ | STOCK | null |

NYSE Arca 상장 ETF도 `AMEX`로 표시된다. 레버리지 판정은 `leverageFactor > 1`로 한다.

**일봉 이력**

| 종목 | 개수 | 범위 | 4일 넘는 공백 |
| --- | --- | --- | --- |
| VOO | 4040 | 2010-09-09 ~ | 2012-10-26 → 10-31 (허리케인 샌디 휴장) |
| QQQ | 6934 | 1999-03-10 ~ | 2001-09-10 → 09-17 (9·11), 2006-12-29 → 2007-01-03 (포드 전 대통령 장례), 2012 샌디 |

공백은 모두 실제 휴장이다. 일봉 이력은 문서의 "2021-11-30 이후"보다 훨씬 길다.

**일봉 시각**: `timestamp`는 미국 현지 자정을 KST로 표현한 값이다. 서머타임 중에는 `13:00+09:00`, 표준시에는 `14:00+09:00`. **저장할 때는 시각이 아니라 미국 거래일(date)로 변환해 키로 쓴다.**

**일봉 값의 기준 (VOO 2026-09-30)**: 일봉 시가 704.58은 정규장 첫 1분봉(22:31 KST 봉) 시가와 같고, 종가 700.86은 마지막 1분봉 종가(700.73)가 아닌 공식 종가(클로징 옥션)다. 즉 **확정된 일봉은 정규장 공식 OHLC**다.

**진행 중 일봉**: 조회 시각 2026-10-01 16:11 KST(미국 10-01 정규장 시작 전)에 이미 `2026-10-01` 일봉이 데이마켓 체결로 채워져 있었다 (VOO 거래량 27,463). 몇 분 사이에 종가가 바뀌는 것도 관찰했다 (QQQ 748.17 → 748.19). 이 봉은 정규장 이후 정규장 값으로 대체된다.

**미국 세션 (`/market-calendar/US`, 서머타임 중, KST)**: 데이마켓 09:00–17:00, 프리마켓 17:00–22:30, 정규장 22:30–05:00(+1일), 애프터마켓 05:00–08:50(+1일). 미국 날짜 D의 거래는 KST D일 09:00부터 D+1일 08:50까지다.

**1분봉**: 데이마켓 시간에도 1분봉이 있다. 체결이 없는 분은 **봉이 빠진다** (30분 중 2분 누락, 거래량 0 봉은 없음). FAQ의 "거래량 0 봉" 설명은 국내 기준으로 보이며, 미국 1분봉은 빠진 분을 허용하도록 검증한다.

**수정주가 (NVDA 2024-06-10 10:1 분할)**: `adjusted=true`는 분할 전 종가를 1/10로 보정(1208.88 → 120.888, 거래량 ×10), `adjusted=false`는 원래 값을 준다. 백테스트는 `adjusted=true`, 체결 가격 표시는 필요하면 `false`를 쓴다.

**현재가 (`/prices`, 2026-10-02 10:13 KST, 데이마켓 중)**: 응답 항목은 `symbol`, `timestamp`(마지막 체결 시각, KST 오프셋), `lastPrice`(문자열), `currency`뿐이다. 전일 대비·호가·거래량은 없다. 데이마켓 시간에도 체결 가격이 나온다. 그래서 화면의 "장 마감 대비"는 저장된 마지막 정규장 종가로 계산한다.

**토큰**: 실행마다 새 토큰을 발급했고 이전 토큰 무효화로 인한 문제는 없었다 (동시 사용 프로세스 없음).

## 8. 수수료 확인 (2026-10-02)

- `GET /api/v1/accounts` → `GET /api/v1/commissions` (계좌 헤더 필요, 읽기 전용, 일회성 조회). 미국(`US`) `commissionRate` = **0.001 (0.1%)**, 국내(`KR`) 0.00015. 미국의 `endDate`가 조회 당일로 내려왔지만, 토스증권 공지상 0.1%는 2025-12-01부터의 **표준 요율**이다.
- 공식 규칙 ([수수료 및 증거금](https://corp.tossinvest.com/ko/business?tab=commission), [표준 위탁수수료율 변경 안내](https://corp.tossinvest.com/ko/post?type=notice&id=17106&category=52)):
  - 미국주식 위탁수수료: 매매거래대금의 0.1%, **$0.01 미만 절사**. 체결금액 $10 이하 주문과 주식모으기 매수는 무료
  - 매도 시 SEC Fee: max(매도거래대금 × 0.00206%, $0.01), 소수점 셋째 자리에서 반올림 (2026-04-02 체결분부터)
  - 환전: 스프레드 1% 기준, 국내 영업일 09:00~15:30 0.05%, 그 외 0.5%
- 모의 체결(`CostModel`)은 위 위탁수수료·SEC Fee를 반영한다. 환전 비용과 $10 이하 무료는 반영하지 않는다.

## 9. 실제 계좌 기록과 소수점 거래 (2026-10-02, 공식 명세 v1.2.19)

"나 카피 봇"의 실제 나 비교(roadmap N1·N4)와 소수점 모의 체결(N2)을 위해 조사했다. 출처는 `https://openapi.tossinvest.com/openapi-docs/latest/openapi.json`(v1.2.19)과 `faq.md`, 그리고 실제 계좌 1회 조회(맨 아래 "실측", ✅). 개인 계좌의 종목·금액은 이 문서에 적지 않는다.

### 주문 기록 `GET /api/v1/orders`

| 항목 | 공식 문서 |
| --- | --- |
| 조회 기간 | `from`·`to`(주문 생성일, KST)를 비우면 **계좌 개설 이후 전체 기간** |
| 페이지 | `status=CLOSED`(체결·취소·거부 등 종료 주문)는 `limit` 최대 100, `cursor`로 이어서. `status=OPEN`은 전량 |
| 포함 범위 | **앱·WTS로 낸 주문도 채널과 무관하게 포함, 소수점 주문·예약 주문도 포함.** 장전·장후 시간외종가처럼 Open API가 지원하지 않는 호가 유형만 빠진다 |
| 한 행 | 주문 1건 = 1행. 나눠 체결되면 `execution.averageFilledPrice`(평균)·`filledQuantity`(합계)·`filledAt`(마지막 체결)로 합산. 건별 체결 REST는 없음 |
| 수량·금액 형식 | `quantity`, `execution.filledQuantity`, `orderAmount`, `filledAmount`, `commission`, `tax` 모두 **decimal 문자열** → 소수점 수량이 그대로 온다 |
| 금액 주문 표시 | `orderAmount`(USD)는 금액 기반 US 시장가 매수에만 값이 있고 그 외 `null` |
| 필터 | `symbol`로 종목별 조회 가능. 계좌 헤더 `X-Tossinvest-Account` 필요 (`GET /api/v1/accounts`의 `accountSeq`) |

### 보유 주식 `GET /api/v1/holdings`

종목별 `quantity`(decimal), `averagePurchasePrice`, `lastPrice`, 평가금액·손익, 전체 투자원금(`totalPurchaseAmount.usd`)을 준다. Rate limit 그룹 `ASSET`. 주문 기록을 다시 적용한 결과가 보유 수량과 맞는지 대조하는 데 쓴다.

### 소수점 거래 규칙 (주문 생성, 실거래 단계 참고)

- 매수는 **금액 주문(`orderAmount`, USD, US 시장가 전용)**으로만 소수점이 된다. 수량(`quantity`) 소수점은 **US 시장가 매도에만** 허용되고, 소수점 매수를 수량으로 보내면 `400`.
- 소수점 수량은 **소수점 6자리**까지.
- 금액 주문과 소수점 수량 주문은 **정규장 시작부터 정규장 종료 1시간 전까지만** 접수 (`422 amount-order-outside-regular-hours` / `fractional-quantity-outside-regular-hours`).
- 토스증권 안내 기준 금액(소수점) 주문이 가능한 미국 종목은 약 3천 개이고, 주식 모으기는 그 종목에 한해 1,000원부터 소수점으로 산다. 주식 모으기 매수와 체결금액 $10 이하 주문은 위탁수수료가 없다 (8절).

### 이 프로젝트에 주는 영향

- **실제 나(N4):** 주문 기록만으로 매수 날짜·소수점 수량·평균 체결가·수수료를 받을 수 있어, 장 마감 가격으로 "실제 나" 곡선을 다시 그릴 수 있다. 1달 치 기록만 있어도 시작할 수 있다.
- **소수점 모의 체결(N2):** 월 $675처럼 주가보다 적은 금액도 그대로 살 수 있게 모의 체결을 **금액 기준·소수점 6자리**로 바꾼다. 실제 토스 금액 주문과 같은 방식이고, 다음 날 시가 체결(정규장 시작)은 금액 주문 접수 시간 안이다.

### 실측 (2026-10-02, 실제 계좌 읽기 전용 1회 조회) ✅

`accounts` → `orders?status=CLOSED`(100건씩 cursor) → `holdings` 순서로 읽고 형식과 집계만 확인했다. 원본 응답은 저장하지 않았다.

| 항목 | 결과 | 영향 |
| --- | --- | --- |
| 계좌 | `accounts[]` = `accountNo`, `accountSeq`, `accountType`. 계좌 1개 | `accountSeq`를 계좌 헤더로 쓴다 |
| 기간·양 | 기간을 비우면 계좌의 첫 주문부터 나왔다 (1년 남짓, 수백 건, 7페이지). 문서대로 | 전체 기록을 한 번에 받을 수 있다 |
| 호출 한도 | 주문 조회 그룹 **초당 5회**, 넘으면 `429` + `Retry-After`(1.5초 안팎) | 페이지마다 한도를 지키고 `429`면 기다린다 |
| 통화 | 미국 주문은 전부 `USD`. **원화(환전) 금액은 주문에 없다** | "실제 나"는 달러로 계산한다. 원화 기준이 필요하면 환율 API를 따로 쓴다 |
| 상태 | `FILLED`, `CANCELED`, `REPLACE_REJECTED` 등. 체결 여부는 `execution.filledQuantity > 0`으로 판단 | 취소·거부 주문은 건너뛴다 |
| 소수점 | 체결의 약 30%가 소수점 수량, **최대 소수점 6자리** (문서와 같음) | 모의 체결도 6자리로 맞춘다 |
| `orderAmount` | **체결된 주문 전부에 값이 있었다** (매도·지정가 포함). 문서("금액 기반 시장가 매수에만, 그 외 null")와 다르다 | `orderAmount`로 금액 주문(주식 모으기 포함)을 구분할 수 없다. 매수 금액은 `execution.filledAmount`를 쓴다 |
| 수수료 | 체결의 일부는 `commission` 0 (주식 모으기·$10 이하 무료로 보인다) | 실제 비용은 기록의 `commission`을 그대로 쓴다 |
| 보유 대조 | 종목별 (매수 − 매도) 체결 수량이 대부분 `holdings`와 정확히 맞았다. **소수 종목에서 소수점 이하 작은 차이**(기록상 판 수량이 산 수량보다 많음)가 있었다 | 주문 기록에 없는 입고(이벤트 주식 지급, 주식 모으기 일부 등으로 추정)가 있을 수 있다. 차이는 "기록 밖 입고"로 보정하고 화면에 알린다 |
| 보유 없음 | 보유 종목이 없으면 `holdings.items`가 빈 배열 (문서대로) | 다 판 계좌도 기록으로 "실제 나"를 그릴 수 있다 |
